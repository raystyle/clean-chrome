# G002:补丁锚定与字节产物工作流

> 补丁脚本（patches\apply-auto-allow.py）写锚、验证与一切字节级产物（diff/patch/源码片段）的工作流;坑对照表为 M001 至 M003,M011 至 M013,M017,M020,M023 至 M026 的权威处置落位（构建环境类坑在 R001 十节）。承 ADR-0003 双形态纪律。

## 一、写锚工作流（实证做法,照序执行）

1. **先读目标树实际签名**:`rg` 目标 API 在当前 tag 的签名与用法再落字节,不凭旧记忆或旧文档写（M023;GetVar 双参与单参即例）
2. **锚定三模式各司其职**:纯增量内容用 before/after 插入;短路整段逻辑必须用 replace 把目标块整块换成注释,禁止提前 return（Chromium 全树 -Wunreachable-code-aggressive + -Werror,死码是硬错误,M011）
3. **行为抑制优先单一开关**:优先改 feature/pref 默认值或行为方法体;不动对象创建与窗口装配（成员未必可空,M012 启动即崩的前车之鉴）
4. **幂等 marker 必须来自 NEW 内容**:marker 是打完补丁才存在的字节（.invalid 域名、clean-chrome 注释等）,用上游已有片段当 marker 该锚永久误判 skip（M017）
5. **加锚后三数对账**:main() 里 edit_file 调用数 = 锚常量数 = 输出 [ok]+[skip] 行数;编译通过不等于锚生效,行为验收是唯一可信终验（M013 幽灵锚）
6. **双形态等价验证**:改锚或升 tag 先在仓库外沙盒 git apply 后字节比对两形态;沙盒必须放在任何 git 仓库之外,并核对实际落盘变更数,exit 0 不代表应用了任何东西（M026）

## 二、字节产物工作流

- **diff/patch/源码类字节产物一律在 Git Bash 里重定向落盘**（`git diff > f`）或 `cmd /c` 原样透传;PowerShell 管道按行对象传递再按系统换行（CRLF）重组,utf8NoBOM 只保证无 BOM 不保证换行（M025）
- **多行插入块不用 PS here-string**（收尾换行语义陷阱）,用显式拼接;多字符替换写 `[string]` 字面量,`.Replace([char]x,...)` 会错配 char 重载且非终止性失败假成功（M001/M002）
- **git diff --no-index 传参一律正斜杠**,生成后 `Select-String '^diff --git'` 自检再落盘（M003）
- **跨平台分发脚本按最老目标 python 写**（mac CLT 3.9.6）:写文件用 `path.open("w", encoding="utf-8", newline="")` 显式句柄,不用 3.10+ 才有的 `write_text(newline=)`（M020）

## 三、页面行为探针纪律

- 页面可观测副作用类探针（getter/Proxy 陷阱/console 行为）一律走**裸 CDP**:fetch /json/list 至 WebSocket 至 Runtime.evaluate 的 .mjs 范本（S006 四节四脚本）
- 不用 bh eval 做行为归因:bh 是 daemon 求值模型,eval 跑在 Node 进程,console.* 是 Node 的 console,页面对象根本不存在,读到的全是 Node 侧噪音（M024）

## 四、坑对照表（权威落位）

| M | 现象 | 根因 | 正确处理 |
| --- | --- | --- | --- |
| M001 | PS here-string 拼补丁文本,插入内容与锚行粘连、末尾空行丢失 | here-string 收尾换行是闭引号终止符不属内容 | 多行插入块用显式拼接;产出先 diff 再采用 |
| M002 | `.Replace([char]0x2192,'->')` 抛异常且非终止,后续语句带旧值假成功 | 字符串长度 2 匹配到 char 重载 | 多字符替换写字面量;脚本加 `$ErrorActionPreference='Stop'` |
| M003 | `git diff --no-index` 传反斜杠路径,输出头带引号,后处理全落空 | git 对含反斜杠路径按需加引号转义 | 传参一律正斜杠;落盘前 `^diff --git` 自检 |
| M011 | 源码内提前 return 短路,编译报 -Werror,-Wunreachable-code | 全树开 -Wunreachable-code-aggressive,死码是硬错误 | replace 模式整块换注释;补丁脚本因此三模式 |
| M012 | 剔除窗口装配对象创建块,浏览器启动即崩 | 成员并非处处可空,别处直接解引用 | 动对象图前全文件 grep 使用点;抑制走 feature/pref 默认值 |
| M013 | 锚常量已加,行为却不变:edit_file 调用从未写进 main() | 常量与调用分离,加锚不改调用无报错 | 加锚后三数对账（调用=常量=ok+skip）;行为验收是唯一终验 |
| M017 | 新锚首跑即 `[skip] already patched`,实际从未打过 | marker 用了上游本来就有的字节 | marker 必须来自 NEW 内容;核对 [ok] 数等于新增锚数 |
| M020 | 补丁脚本分发到 lan-mac 首个写入即 TypeError | `write_text(newline=)` 是 py3.10+,mac CLT 是 3.9.6 | 按最老目标 python 写;显式句柄 open(newline="") |
| M023 | 新锚用旧记忆的 API 签名,增量编译即挂 | 没先读目标 tag 实际头文件 | 写锚前 rg 目标树当前签名（一节流程 1） |
| M024 | bh eval 里 console 探针读到的 stack 是 Node 的 | bh 是 daemon 求值模型,页面对象不存在 | 页面行为探针一律裸 CDP（三节） |
| M025 | PS 管道落盘的 diff 追加进 .patch 后 git apply 报不适用 | PS 管道把 LF 全改写 CRLF,上下文行带 \r | Git Bash 重定向落盘;诊断换行用 `tr -cd '\r' \| wc -c` 数字节,不信 grep -c |
| M026 | 仓库子目录里 git apply,34 文件全部静默 Skipped 且 exit 0 | 子目录调用默认只应用触碰当前目录的路径 | 沙盒放任何 git 仓库之外;判据含实际落盘变更数 |
